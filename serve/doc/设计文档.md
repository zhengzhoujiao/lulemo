## 1. 系统概述

「噜了么」后端提供账号体系与数据持久化能力，前端 Vue3 WebApp 通过 REST API 完成：

- 用户注册 / 登录（用户名 + 密码，无需手机/邮箱验证）
- 噜（Masturbation）行为记录的增删查
- 统计数据计算（连续未噜天数、按天/周/月聚合）
- 身份角色持久化（影响「今日噜么」随机概率）

---

## 2. 技术架构

```
前端 (Vue3 + Vite)
        │  HTTP/HTTPS (JSON)
        ▼
后端 (FastAPI / Python 3.12)
  ├── 路由层   app/routers/
  ├── Schema   app/schemas/   ← Pydantic v2 请求/响应校验
  ├── 模型层   app/models/    ← MongoDB 文档映射
  └── 核心层   app/core/
        ├── config.py   ← 环境变量 (.env)
        ├── database.py ← Motor 异步客户端
        └── security.py ← bcrypt 密码哈希 + Jose JWT
        ▼
MongoDB 数据库 (lulemo)
  ├── users    集合
  └── records  集合
```

## 3. 数据库设计

### 3.1 数据库信息

| 项目 | 值 |
|---|---|
| 数据库名 | `lulemo` |
| 字符集 | UTF-8（MongoDB 默认） |
| 时区规范 | 所有时间字段均存储 UTC，返回时保持 UTC（前端按需转换） |

### 3.2 users 集合

**说明**：存储用户账号信息。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | ObjectId | 自动 | 用户唯一标识 |
| `username` | String | ✅ | 用户名，3~20字符，全局唯一 |
| `password_hash` | String | ✅ | bcrypt 哈希值，不可逆 |
| `identity_role` | String | ✅ | 身份角色，枚举值见下方 |
| `created_at` | DateTime(UTC) | ✅ | 注册时间 |
| `updated_at` | DateTime(UTC) | ✅ | 最后更新时间 |

**identity_role 枚举值**：

| 值 | 含义 | 噜概率 |
|---|---|---|
| `balanced` | 平常心 | 50% |
| `sigma` | 西格玛男人 | 10% |
| `chaos` | 混沌乐子人 | 85% |

**索引**：

```js
db.users.createIndex({ "username": 1 }, { unique: true })
```

**文档示例**：

```json
{
  "_id": ObjectId("664a1b2c3d4e5f6a7b8c9d0e"),
  "username": "deer_boy",
  "password_hash": "$2b$12$...",
  "identity_role": "sigma",
  "created_at": ISODate("2026-05-15T06:00:00Z"),
  "updated_at": ISODate("2026-05-15T06:00:00Z")
}
```

---

### 3.3 records 集合

**说明**：存储每一次噜（Masturbation）行为记录，每次行为写入一条文档。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | ObjectId | 自动 | 记录唯一标识 |
| `user_id` | String | ✅ | 关联用户 `_id`（字符串形式） |
| `timestamp` | DateTime(UTC) | ✅ | 行为发生时间（前端传入，支持历史补录） |
| `date` | String | ✅ | `YYYY-MM-DD` 格式，冗余存储便于日期聚合 |
| `note` | String | 否 | 用户备注，最长 500 字符，默认为空字符串 |
| `created_at` | DateTime(UTC) | ✅ | 记录写入时间（服务端自动填充） |

**索引**：

```js
// 按用户 + 时间倒序查询（列表页主查询）
db.records.createIndex({ "user_id": 1, "timestamp": -1 })

// 按用户 + 日期聚合（统计页查询）
db.records.createIndex({ "user_id": 1, "date": 1 })
```

**文档示例**：

```json
{
  "_id": ObjectId("664a2c3d4e5f6a7b8c9d0e1f"),
  "user_id": "664a1b2c3d4e5f6a7b8c9d0e",
  "timestamp": ISODate("2026-05-15T14:30:00Z"),
  "date": "2026-05-15",
  "note": "",
  "created_at": ISODate("2026-05-15T14:30:05Z")
}
```

## 4. 接口文档

### 全局约定

- **Base URL**：`http://localhost:8000/api/v1`
- **Content-Type**：`application/json`
- **鉴权方式**：需要鉴权的接口请在 Header 中携带 `Authorization: Bearer <access_token>`
- **时间格式**：ISO 8601（如 `2026-05-15T14:30:00Z`）

---

### 4.1 认证模块

#### POST `/auth/register` — 注册账号

注册新用户，注册成功直接返回 Token（无需二次登录）。

**请求体**

```json
{
  "username": "deer_boy",
  "password": "abc123456"
}
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `username` | string | ✅ | 3~20字符，只允许字母/数字/下划线/中文 |
| `password` | string | ✅ | 6~64字符 |

**成功响应** `201 Created`

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "user_id": "664a1b2c3d4e5f6a7b8c9d0e",
  "username": "deer_boy",
  "identity_role": "balanced"
}
```

**失败响应**

| HTTP 状态码 | detail | 说明 |
|---|---|---|
| 409 | 用户名已被占用 | 用户名重复 |
| 422 | validation error | 参数格式不合法 |

## 5. 认证机制

采用 **JWT Bearer Token** 无状态认证：

1. 注册/登录成功后服务端签发 `access_token`（HS256，默认有效期 7 天）
2. 客户端在所有需要鉴权的请求中携带 Header：
   ```
   Authorization: Bearer <access_token>
   ```
3. Token 失效后客户端需重新登录
4. 密码使用 **bcrypt**（cost factor 12）单向哈希存储，服务端不可还原明文

### Token Payload 结构

```json
{
  "sub": "664a1b2c3d4e5f6a7b8c9d0e",  // user_id
  "exp": 1748000000                     // 过期时间戳（Unix）
}
```

## 6. 错误码规范

所有错误响应统一结构：

```json
{
  "detail": "错误描述（中文）"
}
```

| HTTP 状态码 | 常见场景 |
|---|---|
| 400 Bad Request | 参数格式错误（如非法 ObjectId） |
| 401 Unauthorized | Token 缺失、无效或过期；账密错误 |
| 404 Not Found | 资源不存在或无权访问 |
| 409 Conflict | 用户名已被占用 |
| 422 Unprocessable Entity | Pydantic 校验失败（字段格式/长度不合法） |
| 500 Internal Server Error | 服务端未预期错误 |

## 7. V2.0 扩展（Mongo 集合 / 指标 / 路由摘要）

> 与产品说明 `doc/噜了么.md` V2.0 对齐。时间口径：**打卡与排行使用 `Asia/Shanghai` 的日历日 `YYYY-MM-DD`**。

### 7.1 新增集合

| 集合 | 说明 |
|---|---|
| `check_ins` | `(user_id, local_date)` 唯一；`status` ∈ `deer \| none`（噜了 / 没噜）；支持补卡回溯 **90** 天 |
| `posts` / `comments` | 广场（七嘴八舌）帖与评论，`author_display_name` 为展示名快照 |
| `teams` / `team_members` | 小队与成员；`team_members.user_id` **全局唯一**（一人同时仅一个小队）；`auto_kick_miss_gt`：自然月缺席打卡天数 **严格大于**该值则移出小队 |
| `users.region` | `{ province_code, city_code, district_code, *_name }`，**新注册用户必填** |

### 7.2 排行榜指标

- **噜数目（count）**：时间窗内 `records` 事件条数按省/市/区桶或按小队成员汇总。  
- **噜率（rate）**：仅统计时间窗内 **`check_ins` 总条数 > 0** 的用户；对每个用户算 `deer天数/该用户打卡天数`，再在桶内对所有此类用户分子分母各自求和后相除：**Σdeer / Σ打卡天数**。  
- **小队榜**：仅统计成员数 **≥10** 的队伍。
- **`GET /rankings`**：`scope=province|city|district|team`，`period=day|week|month|year`，`metric=rate|count`，`anchor`（可选，`YYYY-MM-DD`，默认上海当日）。

### 7.3 主要 API（均需 Bearer，除注册/登录）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/check-ins` | 当日或补卡 upsert `{ local_date?, status }` |
| GET | `/check-ins/month` | `year`/`month`，返回 `days: { yyyy-mm-dd: status }` |
| GET | `/rankings` | 排行聚合 |
| GET/POST | `/social/posts`、`DELETE ...` | 广场（七嘴八舌）帖 |
| GET/POST | `/social/posts/{id}/comments` | 评论 |
| POST | `/teams`、`GET /teams/mine`、`GET /teams/{id}`、`POST .../join`、`POST .../leave` | 小队（首版不含群聊） |
| GET | `/teams/{id}/stats` | 队内 `record_count`、`deer_rate` |
| PATCH | `/users/me/display-name` | `{ plaza_display_name }` |

### 7.4 索引（启动时在 `main._ensure_indexes`）

- `check_ins`: unique `(user_id, local_date)`  
- `team_members`: unique `(team_id, user_id)`，unique `user_id`  
- 其余：`posts`、`comments`、`users.region.province_code`（sparse）等见 `serve/app/main.py`。
